# 图书管理系统 · 关系模式（ER → 关系模式转换）

> 作者：张展博 · 2026-11-25
> 数据库：MySQL 8.0 · InnoDB · UTF-8
> 所有关系模式均已达到 3NF（详见 03.1_范式检查说明.md）

---

## 一、主关系模式（6 张表）

### 1.1 Reader（读者）
```sql
Reader(reader_id, name, sex, phone, email, reg_date, status)
-- PK: reader_id
```
- 主码：`reader_id`
- 无外码

### 1.2 Admin（管理员）
```sql
Admin(admin_id, name, account, pwd, role)
-- PK: admin_id
-- UK: account （账号唯一）
```
- 主码：`admin_id`
- 无外码
- `account` 建唯一索引

### 1.3 Category（分类，支持多级）
```sql
Category(cat_id, cat_name, parent_id)
-- PK: cat_id
-- FK: parent_id → Category.cat_id
```
- 主码：`cat_id`
- 外码：`parent_id`（自引用，根节点为 NULL）

### 1.4 Book（书籍）
```sql
Book(book_id, isbn, title, author, publisher, pub_date, descr, cat_id)
-- PK: book_id
-- FK: cat_id → Category.cat_id
-- UK: isbn （ISBN 理论上唯一，但同一书有不同版本 ISBN 可能不同，可选唯一）
```
- 主码：`book_id`
- 外码：`cat_id`

### 1.5 Copy（书籍副本）
```sql
Copy(copy_id, book_id, asset_no, location, is_available)
-- PK: copy_id
-- FK: book_id → Book.book_id
-- UK: asset_no （馆藏编号唯一）
```
- 主码：`copy_id`
- 外码：`book_id`

### 1.6 Borrow（借阅记录）
```sql
Borrow(borrow_id, reader_id, copy_id, borrow_date, due_date, return_date, status, is_overdue, admin_id, handle_time)
-- PK: borrow_id
-- FK: reader_id → Reader.reader_id
-- FK: copy_id   → Copy.copy_id
-- FK: admin_id  → Admin.admin_id （可空）
```
- 主码：`borrow_id`
- 外码：`reader_id`、`copy_id`、`admin_id`（可空）

## 二、ER → 转换规则对照

| ER 元素 | 转换方式 | 说明 |
|---------|----------|------|
| 实体 Reader / Admin / Category / Book / Copy / Borrow | 每张实体一张关系表，属性直接映射 | — |
| 自引用联系（Category 父子） | 在 Category 表里加 `parent_id` 外码指向自己 | 1:N 自引用，外码放 N 方 |
| Book → Copy（1:N 拥有） | 外码 `book_id` 放 Copy 表 | 1:N 外码放 N 方 |
| Category → Book（1:N 归属） | 外码 `cat_id` 放 Book 表 | 1:N 外码放 N 方 |
| Reader → Borrow（1:N 发起） | 外码 `reader_id` 放 Borrow 表 | 1:N 外码放 N 方 |
| Copy → Borrow（1:N 被借阅） | 外码 `copy_id` 放 Borrow 表 | 1:N 外码放 N 方 |
| Admin → Borrow（1:N 处理） | 外码 `admin_id` 放 Borrow 表（可空） | 联系可选，外码允许 NULL |

**注意**：本系统**没有 M:N 联系**（"读者-书"本来是 M:N，但借书实际借的是副本，所以 Borrow 把"读者-副本"变成了 1:N 的外码汇聚，而"副本"→"书"是 1:N）。因此转换后不需要额外的中间表。

## 三、冗余字段说明（反范式设计 + 理由）

| 表 | 字段 | 理由 |
|----|------|------|
| Copy | `is_available` | 冗余存储"是否在馆"，避免每次都要 COUNT Borrow 表判断运行中借阅；由应用层 + 事务维护一致性 |
| Borrow | `is_overdue` | 冗余存储"是否曾逾期"，由 `return_book` 在归还时按当时是否超期写入、`renew_book` 续借时归 0；当前无每日触发器 |
| Borrow | `status` | 冗余状态字段（在借/已归还/已逾期），方便前端按状态筛选 |

**3NF 说明**：去掉上述 3 个冗余字段后，所有关系均满足 3NF。保留它们是出于**查询性能**考虑，由借还续存储过程在事务内保证一致性；当前不建每日触发器。

## 四、给谭博友的接口约定

> 以下字段类型由 `03_数据字典.xlsx` 推导；实际实现以 `src/backend/sql/04_init.sql` 为准，数据字典与 SQL 冲突时按 SQL 口径执行并报告差异。

| 字段 | MySQL 建议类型 | 备注 |
|------|----------------|------|
| 所有 _id | `CHAR(16)` 或 `VARCHAR(32)` | 统一用字符串主键，方便手写测试数据 |
| 日期类 | `DATE` | 仅存年月日 |
| 时间类 | `DATETIME` | 精确到秒 |
| is_available / is_overdue / status | `TINYINT(1)` 或 `INT` | 0/1 标记 |
| descr | `TEXT` | 书籍简介 |
| 密码 | `VARCHAR(255)` | 存 SHA256 哈希值，**绝对不能明文** |
