# 设计准则

## 1. 依据与范围

- 后端与数据库设计以课程任务书为最高依据；前端框架、语言和文件保持原计划不动。
- 数据库使用远程 MySQL 9.7.2 实例，存储引擎 InnoDB；本地不安装、不初始化数据库服务端。任务书要求为 8.4 LTS，当前环境差异已记录。
- 程序形式为 Java 命令行应用，不引入 Spring 等框架。

## 2. 数据库设计准则

- 至少包含 5 张核心表；本仓库按 6 张表设计：

  | 表名 | 含义 |
  | --- | --- |
  | `reader` | 读者 |
  | `category` | 图书分类 |
  | `book` | 图书书目 |
  | `book_copy` | 馆藏副本 |
  | `borrow_record` | 借阅记录 |
  | `reservation` | 预约记录 |

- 多对多联系通过中间表正确落地：读者与图书之间通过 `borrow_record` / `reservation` 关联。
- 至少包含一个涉及 3 张及以上表的查询，例如借阅记录连接读者、副本、书目。
- 至少包含一个事务业务场景：`borrow_book`，需检查读者状态与副本可借状态，插入借阅记录并更新副本状态，任一步失败整体回滚。
- 关系模式原则上达到 3NF；如需反范式冗余，必须在数据字典中写明理由。
- 显式定义主键、外键、唯一约束、`NOT NULL`、`CHECK` 与合适索引；外键列和高频查询列应有索引。
- 字符集统一 `utf8mb4`；排序规则使用 `utf8mb4_unicode_ci` 或项目统一约定的兼容规则。
- 禁止向公共大模型提交真实密码、个人敏感信息或未经授权的数据。

## 3. 应用结构准则

```text
src/backend/main/java/com/library/
├── Main.java                 命令行入口
├── model/                    数据对象
├── util/DBUtil.java          连接管理
├── dao/                      数据访问接口
├── dao/impl/                 数据访问实现
└── service/                  业务逻辑与事务
```

前端源码放在 `src/frontend/`，技术选型沿用原计划，不在本次后端规范范围内。

- DAO 只负责 SQL 执行与结果映射；Service 负责业务规则与事务边界；Main 只负责交互。
- 每个核心实体提供完整 CRUD；至少 2 条多表查询；至少 1 个事务业务。
- 配置外置：主机、端口、库名、用户名从环境变量或本地 `.env` 读取，密码只写本地 `.env`。
- 连接 URL 必须显式指定字符编码与时区，避免环境差异导致乱码或时间偏移。

## 4. 交付与验证

- 数据库脚本统一放在 `docs/04_数据库实现/`：
  - `create_tables.sql`
  - `insert_data.sql`
  - `query.sql`
- 每张核心表不少于 10 条测试数据，关联数据必须满足参照完整性。
- 查询脚本不少于 8 条，覆盖单表条件、多表关联、分组统计、嵌套查询和复杂业务查询。
- 所有 AI 生成的 E-R 图、关系模式、SQL 与 Java 代码必须人工审核并在远程库中实际验证，记录见 [AI_USAGE.md](AI_USAGE.md)。
