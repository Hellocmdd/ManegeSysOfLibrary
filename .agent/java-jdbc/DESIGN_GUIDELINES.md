# 设计准则

## 1. 依据与范围

- 后端与数据库设计以课程任务书为最高依据；前端框架、语言和文件保持原计划不动。
- 数据库默认使用远程 MySQL 9.7.2 实例，存储引擎 InnoDB；任务书要求为 8.4 LTS。仓库根目录 `docker-compose.yml` 提供 `mysql:8.4` 本地可选方案，切换后必须重新跑真库集成测试。
- 程序形式为 Java 命令行应用，不引入 Spring 等框架。
- 表结构、字段类型、约束与存储过程签名的唯一权威是 `src/backend/sql/04_init.sql` 与 `05_存储过程.sql`；`src/backend/sql/java/` 下三份脚本是同口径同步副本，修改必须先改权威文件。

## 2. 数据库设计准则

- 至少包含 5 张核心表；本仓库按权威口径设计 6 张表：

  | 表名 | 含义 |
  | --- | --- |
  | `Reader` | 读者 |
  | `Admin` | 管理员 |
  | `Category` | 图书分类（支持多级） |
  | `Book` | 图书书目 |
  | `Copy` | 馆藏副本 |
  | `Borrow` | 借阅记录 |

- 当前设计**不包含 M:N 联系与预约表**："读者—书"已通过 `Copy` + `Borrow` 拆成两个 1:N。若教师要求必须展示 M:N，需另立需求再补实体与中间表，不得私自加 `reservation`。
- 至少包含一个涉及 3 张及以上表的查询，例如借阅记录连接读者、副本、书目和管理员。
- 至少包含一个事务业务场景：`borrow_book`，校验读者状态/在借数与副本在馆状态，写入借阅记录并更新副本状态；事务与行锁在存储过程内实现，任一步失败整体回滚。
- 关系模式原则上达到 3NF；保留 `Copy.is_available`、`Borrow.status`、`Borrow.is_overdue` 三个冗余字段，由借还续过程在事务内维护，无每日触发器。
- 显式定义主键、外键、唯一约束、`NOT NULL`、`CHECK` 与合适索引；外键列和高频查询列应有索引。
- 字符集与排序规则统一 `utf8mb4` / `utf8mb4_unicode_ci`。函数默认值必须写成表达式形式，如 `DEFAULT (CURDATE())`。
- 禁止向公共大模型提交真实密码、个人敏感信息或未经授权的数据。

## 3. 应用结构准则

```text
src/backend/main/java/com/library/
├── Main.java                 命令行入口
├── model/                    数据对象
├── util/DBUtil.java          连接管理
├── dao/                      数据访问接口
├── dao/impl/                 数据访问实现
└── service/                  业务逻辑与异常转换
```

前端源码放在 `src/frontend/`，技术选型沿用原计划，不在本次后端规范范围内。

- DAO 只负责 SQL 执行与结果映射；Service 负责业务编排、结果复查与异常转换；Main 只负责交互。
- 每个核心实体提供必要查询；借/还/续由 `CallableStatement` 调用权威存储过程，不在 Java 里重写业务 SQL 或另开本地事务。
- 配置外置：主机、端口、库名、用户名从环境变量或本地 `.env` 读取，密码只写本地 `.env`。
- 连接 URL 必须显式指定字符编码与时区，避免环境差异导致乱码或时间偏移。

## 4. 交付与验证

- 权威脚本：`src/backend/sql/04_init.sql`、`05_存储过程.sql`、`06_测试数据.sql`；Java 配套脚本位于 `src/backend/sql/java/`，与权威脚本逐行同口径。
- 测试数据基线：管理员 10 / 分类 11 / 读者 10 / 书籍 20 / 副本 30 / 借阅 15；当前未归还 8（当前逾期 2），曾逾期 4。
- 查询脚本不少于 8 条，覆盖单表条件、多表关联、分组统计、嵌套查询和复杂业务查询。
- 后端单元测试 18 条已通过；真库集成测试位于 `src/backend/test/java/com/library/integration/`，由 `RUN_DB_INTEGRATION=1` 门控，7 个用例已全部执行通过；前端真库冒烟也已通过。
- 所有 AI 生成的 E-R 图、关系模式、SQL 与 Java 代码必须人工审核并在远程库中实际验证，记录见 [AI_USAGE.md](AI_USAGE.md)。
