# AI 辅助使用规范

依据课程任务书“大模型辅助使用要求”制定。

## 1. 允许范围与必须验证项

| 环节 | 允许的辅助行为 | 必须完成的人工验证 |
| --- | --- | --- |
| 需求分析 | 需求提取、业务规则分析 | 确认需求真实、完整、无矛盾 |
| 概念设计 | 实体识别、E-R 图生成 | 核对实体、属性、联系及基数 |
| 逻辑设计 | 关系模式转换、规范化分析 | 独立核对函数依赖与分解结论 |
| SQL 实现 | 建表、测试数据、查询语句生成 | 在远程 MySQL 9.7.2 中实际执行并核验结果 |
| JDBC 编程 | 连接、DAO、事务代码生成 | 编译、运行、测试并逐行解释 |
| 程序调试 | 异常分析、错误定位 | 复现问题并验证修复有效 |

## 2. 硬性要求

- 保留重要 Prompt 及模型回答，记录应能对应到具体设计或代码成果。
- 大模型生成的数据库设计必须经过人工审核。
- 大模型生成的 SQL 必须在实际数据库中运行验证。
- 大模型生成的 Java 程序必须能编译、运行并通过测试。
- 不得直接提交未经理解和验证的 AI 生成结果。
- 不得将真实密码、个人敏感信息或未经授权的数据提交给公共大模型。
- 需至少记录 2 个有代表性的 AI 错误或不合理结果，包含发现、分析、修改与验证全过程。

## 3. 记录位置与模板

记录统一放入 `docs/07_AI辅助过程/`：

- `Prompt记录.md`
- `AI生成结果.md`
- `AI辅助效果评价.md`

单条记录模板：

```markdown
## 记录编号：AI-001

- 日期：
- 任务环节：
- 对应交付物：
- Prompt（脱敏）：
- 模型回答摘要：
- 人工检查发现的问题：
- 修改内容：
- 验证方式与结果：
- 结论：采纳 / 部分采纳 / 弃用
```

提交前需在学习总结中回答课程任务书列出的 8 个问题，并给出至少 2 个AI纠错案例。建议字数约 800 字。
