# docs-style.md — 文档通用规范

适用：仓库内所有 `.md`，包括 `README.md`、线内 `README.md`、`02_设计线/02_关系模式.md`、`00_分工与进度.md` 及最终报告章节。

## 1. 职责边界

- 一份文档只有一个主题；跨主题的内容拆文件，不写成"大杂烩"。
- `00_分工与进度.md` 是进度与交付物的登记表，其他文档不复述它的内容，只引用。
- `src/frontend/README.md` 写"怎么跑、有哪些页面、用到哪些接口"；实现细节与代码风格写在 `.agent/`，不在 README 里重复。
- 数据库事实（表、字段、过程、口径）写进 `.agent/conventions/db-contract.md` 与 `src/backend/sql/*.sql`，README 只写用法。

## 2. 结构

- 开头 3 行内说清"这份文档给谁看、解决什么问题"。
- 用二级标题分节；层级不跳级（`##` 下直接用 `####` 不允许）。
- 能用表格就别用长段落对照（选型、对比、参数、状态值）。
- 每条结论独立成行，不把多个判断塞进一句长句。
- 代码块必须标语言：```` ```python ````、```` ```sql ````、```` ```jinja ````、```` ```bash ````。
- 命令块写清在哪个目录执行、前置条件（如"先激活虚拟环境"）。

## 3. 事实与数字

- **不编造**：没跑过的测试不写"已通过"，没装的环境不写"已安装"，没做的功能不写"已完成"。
- 引用数字（表数量、测试数据条数、报表条数）必须能在仓库里核对到出处；口径变化时同步更新。
- 时间写 `YYYY-MM-DD`；时间点写 `YYYY-MM-DD HH:MM`。
- 版本写具体号（`Python 3.11`、`MySQL 8.0`、`Flask 3.x`），不写"最新版"。
- 未完成、待确认、有阻塞的条目统一用 `TODO(<模块>):` 前缀，并在句末写阻塞原因与依赖方。

## 4. 语言

- 中文为主，专有名词保留英文；中英文之间加空格（`使用 Flask 开发`）。
- 用陈述句和祈使句，不用"我们认为""大概""可能"这类模糊表达；确实不确定时写"待验证：<要验证什么、怎么验证>"。
- 术语全仓统一：`读者` / `图书` / `副本` / `借阅` / `归还` / `续借` / `逾期`；不混用"用户""书籍""册""罚款"。
- 不用表情符号、不用花哨排版；强调用**加粗**，不滥用引用块。

## 5. 命名与链接

- 文件名遵循所在目录的编号约定（`01_`、`02_`…），**不自行改编号、不新增未登记的编号**。
- 文件名用中文描述内容，与 `00_分工与进度.md` 登记表一致。
- 文档间引用用相对路径 Markdown 链接，不用绝对路径、不用 `file://`。
- 截图放 `08_前端页面截图/`，文件名体现页面与状态（如 `03_图书列表_筛选结果.png`），文档里用相对路径嵌入。

## 6. 常见文档骨架

**线内 README**：定位 → 技术选型 → 目录结构 → 环境准备与运行 → 页面/功能清单 → 与其他线的接口 → 已知问题 → 交付清单。

**接口/查询说明**：用途 → 入参（名称、类型、是否必填、取值范围）→ 出参（列名、含义）→ 示例（一条真实可跑的 SQL 或调用）→ 异常与边界。

**报告章节**：本节结论 → 设计与实现要点 → 验证方式与结果 → 不足与改进（如实写，不粉饰）。

## 7. 禁止事项

- 禁止写具体人名、学号、账号、密码、真实连接串。
- 禁止把 `TODO` 当"已完成"表述（"已实现借书，返回码待联调"这种半成品措辞要么标 TODO，要么写实）。
- 禁止复制粘贴同一段内容到多个文档（改为引用一处）。
- 禁止提交带编辑器痕迹的文档（未填的占位符、`<TODO>`、乱码）。
- 禁止在文档里给出与本仓库代码不符的命令或路径。
