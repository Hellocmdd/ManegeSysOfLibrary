# git-workflow.md — 分支、提交与合并

## 1. 分支模型

| 分支 | 用途 | 谁能写 |
| --- | --- | --- |
| `main` | 唯一集成分支，随时可交付 | **只通过 PR 合并**，任何人不得直接 push |
| `feat/<主题>` | 新功能、新页面 | 功能负责人 |
| `fix/<主题>` | 缺陷修复 | 修复者 |
| `docs/<主题>` | 文档、`.agent` 规范 | 文档负责人 |

- 分支一律从最新 `main` 切出；已合并的分支（如 `feat/project-setup`）**不再复用**，新工作重新切分支。
- 主题用中文短语或短横线英文，能看出做了什么：`feat/图书列表页`、`docs/agent-conventions`、`fix/逾期清单口径`。
- 一个分支只做一件事；发现顺手要改的其他问题，单开分支。
- 定期 `git fetch` 并把 `main` rebase 到功能分支（`git rebase origin/main`），不用 `merge main` 回灌，保持线性历史。
- 分支合并后删除远端分支；本地分支可保留到本周结束。

## 2. 提交信息

格式：`<类型>(<模块>): <一句话说明>`，中文，句末不加句号，首行不超过 50 字。

| 类型 | 用途 |
| --- | --- |
| `feat` | 新功能、新页面 |
| `fix` | 修缺陷 |
| `docs` | 文档、注释、`.agent` |
| `refactor` | 不改变行为的重构 |
| `style` | 排版、格式（不影响逻辑） |
| `test` | 测试 |
| `chore` | 依赖、配置、杂项 |

示例：

```
feat(前端): 增加图书列表页与书名模糊查询
fix(前端): 逾期清单漏加 return_date IS NULL
docs(agent): 补齐 .agent 规范与 Python 类型注解要求
```

- 正文（可选）写**为什么**改、影响范围、验证方式；不写"修改了一些代码"。
- 一个提交只含一个逻辑变更；不把格式化与功能混在一次提交里。
- 不提交半成品（跑不起来的代码）；确实要分步提交时，确保每个提交都能启动。
- 禁止 `update`、`fix bug`、`1`、`.` 这类无信息量的信息。

## 3. 提交前检查

按顺序执行，任何一项不过就不提交：

1. `git status` —— 确认没有误改他人文件、没有未跟踪的临时文件。
2. `git diff` / `git diff --cached` —— 逐行看过要提交的内容。
3. 敏感文件检查：`.env`、`config_secret.py`、`*.log`、`__pycache__/`、`.venv/` 不得出现在暂存区（`.gitignore` 已覆盖，仍要肉眼确认）。
4. 可运行性：`python app.py` 能启动，改动涉及的页面能打开。
5. 若改了 SQL：对应查询在真实库跑过，结果条数已核对。
6. 若改了文档：没有遗留占位符、人名、虚构数字。

## 4. 合并流程

1. push 功能分支，在平台上发起 PR 到 `main`。
2. PR 描述包含：改了什么、为什么、怎么验证、影响哪些文件、遗留 TODO。
3. 至少一名其他成员 Review（按 `review.md` 的输出格式），评论未解决不合并。
4. 合并方式用 merge commit 或 squash，二者选一后全组统一；不 force push 已推送的分支。
5. 合并后本地切回 `main` 并 `git pull`，删除已合并的远端分支。

## 5. 回滚与冲突

- 已推送的错误提交用 `git revert`，不改写历史；只有**自己独占、未推送**的提交才允许 `--amend`。
- 冲突解决后必须重新跑一遍验证；不盲目选 "ours/theirs" 整段保留。
- 误提交敏感信息：立即改密码/换密钥，再清理历史，并告知全组；清理历史属高风险操作，先出确认请求。

## 6. 禁止事项（硬性）

- 禁止直接 push `main`、禁止 force push `main`。
- 禁止提交 `.env`、`config_secret.py`、`__pycache__/`、`.venv/`、日志、`*.zip` 交付包。
- 禁止把无关改动塞进同一个提交（`git add .` 前必须看清单）。
- 禁止在未确认的情况下执行 `commit` / `push` / `merge` / `revert` / 删除分支（见 `commit-push-confirm.md`）。
- 禁止用 `git push -f` 覆盖他人分支。
