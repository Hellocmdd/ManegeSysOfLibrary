# comment-style.md — 注释与 docstring 规范

适用：Python、SQL、Jinja2 模板。目标是让注释解释**为什么**，而不是把代码翻译成中文。

## 1. 总则

- 注释写"为什么这样做、约束是什么、什么情况下不能改"，不写"这行在做什么"。
- 代码能自解释时不加注释；命名已经说清的不再重复。
- 注释用中文，标点用全角；专有名词保留英文（`Flask`、`InnoDB`、`LIMIT`）。
- 注释与代码同一次提交更新；改逻辑必须同步改注释，过期注释比没有注释更糟。
- 注释掉的死代码一律删除；确实需要保留的，改成 `TODO(<模块>): <恢复条件>` 并说明原因。

## 2. 行内注释

- 写在被解释代码的上一行，不写在行尾（除非是极短的常量说明）。
- 长度控制在 100 字以内，长说明改写成块注释或 docstring。
- 不写 `# 这里加1` 这种复述代码的注释。

```python
# 借阅计数必须排除已归还记录，否则读者还过书也会被判"已借满"。
# 口径与 05_存储过程.sql 中 borrow_book 的计数条件保持一致。
active = [b for b in borrows if b["return_date"] is None]
```

## 3. docstring

Python 的 docstring **唯一格式**见 `python-style.md` 第 2 节：`"""` 包裹，摘要 + `*Args:` + `*Return:`（可选 `*Raises:`）。此处只补充边界：

- 每个函数、方法必须有；模块顶部必须有；类必须有。
- 不在 docstring 里写作者、日期、修改历史、工单号。
- 不把实现步骤写进 docstring（那是代码的事）；写调用约束、参数来源、返回值语义。
- 生成的文档不必单独维护，docstring 就是文档。

## 4. TODO / FIXME / NOTE

统一格式，三种标记含义不同，不混用：

```python
# TODO(前端): 分类下拉框暂只显示两级，等后端补齐三级分类后改为递归渲染。
# NOTE(前端): 04_init.sql 已补齐字段，查询按权威六表结构编写，不再等待补字段。
# NOTE(前端): 报表"逾期清单"口径为当前未归还，页面标题已写明，不要改成含已归还。
```

- 括号里写**模块归属**（`前端` / `后端` / `设计`），写具体人名无效。
- 一句话说清"要做什么 / 什么条件下能修"，不写"以后优化"。
- 任务完成即删除标记，不留长期 TODO 在交付版本里；**交付前全仓 `TODO(` 数量必须为 0 或每条都有明确阻塞原因**。

## 5. SQL 注释

```sql
-- 报表③：当前逾期清单（口径：未归还且已过应还日期）
-- 说明：Borrow.is_overdue=1 含"曾逾期但已归还"的历史记录，因此这里追加 return_date IS NULL
SELECT r.reader_id, r.name, b.title, br.due_date
FROM Borrow br
JOIN Reader r ON r.reader_id = br.reader_id
JOIN Copy c   ON c.copy_id   = br.copy_id
JOIN Book b   ON b.book_id   = c.book_id
WHERE br.is_overdue = 1
  AND br.return_date IS NULL
ORDER BY br.due_date;
```

- 每条报表 / 复杂查询的**口径**必须用注释写清：时间范围、是否含已归还、是否含子分类、主表是谁。
- 存储过程里的返回码含义写在过程头部注释，与 `AGENT.md` 的返回码表一致。
- 不用 `/* */` 包裹整段旧代码；删除由 git 负责。

## 6. 模板与配置注释

- Jinja2 用 `{# ... #}`，只在解释"为什么这个块要这样组织"时写，不写"这是一个 div"。
- 配置项注释说明单位、默认值来源、能否为空；密钥类不写真实值，只写"从环境变量读取"。
- CSS 用 `/* ... */` 按页面区块分组注释，不逐条属性注释。

## 7. 禁止事项

- 禁止把注释当提交说明（改动说明写 commit message）。
- 禁止注释里出现具体人名、学号、账号、密码。
- 禁止用注释解释明显代码、禁止注释与代码矛盾。
- 禁止 `# noinspection`、`# type: ignore` 之类的静默指令无理由出现。
